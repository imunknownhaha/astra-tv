# Architecture and deliberate limits

- Application owns Room, network, settings, and library dependencies; ViewModel owns screen state and a single reusable ExoPlayer/MediaSession. Compose owns only ephemeral focus/dialog state. Application context prevents leaking activities into the player.
- Room uses stable IDs from source ID plus M3U URL or Xtream kind/provider ID. Refresh inserts/upserts in 500-item batches and prunes stale catalog entries in one transaction. Favorites/history use a separate profile/item relation and survive refresh. This is an incremental database replacement, not an HTTP delta protocol. Changed M3U URLs change identity; duplicate guide IDs never collapse distinct stream URLs.
- Search is debounced 180 ms and uses parameterized local SQLite queries (name/category). Lists load 200 rows at a time; Load more increases the window. This is deliberately simpler than Paging/FTS for the first release. Huge provider catalogs still merit device profiling and FTS if measurements justify it.
- Channel keys use indexed name/ID cursor queries with category restrictions, avoiding an all-channel allocation. Logos use Coil caching and fixed decode areas. HTTP logos are omitted rather than widening image-loader policy.
- Downloads/parsing run on Dispatchers.IO, PIN hashing on Default. M3U is one-pass but retains at most 100,000 imported entries for an atomic refresh; response and character limits bound inputs. Xtream catalogs now stream through Android JsonReader, skipping unused metadata and encrypting/writing 128-entry batches to a hidden pending source. A transaction publishes the completed catalog without retaining the full JSON or the live/movie/series lists in the Java heap. Failed live refreshes retain the existing library; failed optional movie/series endpoints retain their previous entries. Pending rows are removed on failure/cancellation and at startup after a process interruption. Series episode-info responses still use bounded JSONObject parsing. XMLTV is a streaming pull parser retaining a bounded 21-day schedule (maximum 500,000 programs), rejecting DTD declarations. Not a constant-memory ingestion pipeline; very large catalogs need memory profiling on 2 GB TVs.
- Guide queries fetch only the three-hour visible window per composed row, scoped by source and guide ID. LazyColumn virtualizes channels; time cells are bounded to the window. Display offsets use the TV's ZoneId. WorkManager refreshes configured guides at 12-hour intervals with a connected-network constraint; the interval is optional, timing is OS-controlled, and it does not poll constantly. Playlist refresh is manual.
- A Keystore AES-256/GCM key protects source configuration, stream addresses, request headers and logos in Room. Library names/descriptions/favorites remain unencrypted. Keystore failures never fall back to plaintext. Application backup is disabled. The OS sandbox and lock screen remain the device's security boundary.
- Global HTTP opt-in is required for imports and playback, including redirected requests. Manifest cleartext support is necessary for explicit opt-in; the networking policy enforces the default. Stream sources are HTTP(S) only; no UDP, RTSP, file path, SMB or DRM bypass.
- ExoPlayer handles ABR, platform codecs, audio focus, noisy audio, track selection and rendering. App-level reconnection has a three-attempt exponential budget; internal source load retries are disabled so they cannot bypass that budget. A selection change cancels pending retries. No endless reconnects or background playback. MediaSession provides transport keys without an exported playback service.
- Progress snapshots occur every ten seconds, at channel/episode switches, player exit and activity stop. A process kill can lose the last interval. Watched status is derived at >95% duration; there is no manually editable watched flag yet. Continue watching excludes live TV and completed media. Next episode is explicit navigation, not automatic autoplay.
- M3U live metadata includes tvg-id/name/logo, group-title/EXTGRP, VLC HTTP user-agent/referrer and catch-up days/source. `media-type="movie"` opt-in puts M3U items into Movies. Rich movies/series come from Xtream provider catalogs and series-info responses. No invented rating, date, duration, season art or external movie-database enrichment.
- Xtream catch-up uses UTC timeshift URLs and advertised archive duration. M3U catch-up supports `{utc}` / `{start}`, `{utcend}`, `{duration}` Unix-second templates. Other provider-specific formats need adapters. Availability flags do not guarantee the provider permits playback of every listed program.
- Profile restrictions are enforced both in browse SQL and again before playback. The management PIN gates settings, playlist administration, profile management and update configuration. Creating category restrictions requires setting that PIN first. PIN verification uses PBKDF2-HMAC-SHA256, 120,000 iterations, random 128-bit salt, 256-bit result, constant-time comparison. Five wrong entries cause a one-minute session cooldown; this is not an OS parental-control service.
- Manual updates use GitHub's releases/latest endpoint and an exact APK asset name; APKs are HTTPS-only and package/version/signer-checked. The system installer is invoked using FileProvider with a temporary read grant, and requires approval. No update checks run in the background, no arbitrary downloaded code is executed, and no installer is silently invoked.
- Recording was analyzed but not implemented: stream/provider permission, Android TV storage grants, free space, background execution, guide scheduling and device throughput must be established before offering recording controls. External-player support and DRM provisioning are also deferred. No decorative controls imply these features exist.
